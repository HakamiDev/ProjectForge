**Операційна система для команди ШІ-агентів.** Одна команда перетворює звичайну теку на організований офіс: єдина дошка, з якою працюють усі агенти на будь-якій платформі; незалежний контроль якості; керування рішеннями; повний журнал аудиту; показники ефективності з експортом до Power BI та сайт керування, що працює з одного HTML-файлу.

Python 3.9 або новіший, без залежностей, без сервера. Відкритий вихідний код, ліцензія MIT.

Вебсайт: https://hakamidev.github.io/ProjectForge/

## Встановлення

Один рядок, вставлений у термінал. Він завантажує інструмент, запускає його, ставить чотири запитання, а потім відкриває ваш сайт керування.

macOS і Linux (Terminal):

```
curl -fsSL https://raw.githubusercontent.com/HakamiDev/ProjectForge/main/install.sh | bash
```

Windows (PowerShell):

```
irm https://raw.githubusercontent.com/HakamiDev/ProjectForge/main/install.ps1 | iex
```

Сайт також дає змогу заздалегідь обрати платформу та бажану мову; обидва параметри потрапляють до команди встановлення й заздалегідь вибираються в майстрі.

## Які проблеми вирішує

- **Чати забувають.** Правила та описи ролей зберігаються в теці, а не в пам'яті чату, тож будь-який чат може продовжити роботу.
- **Агенти заважають одне одному.** Одна пронумерована дошка; статус «у роботі» блокує рядок; перевірка контрольної суми запобігає конфліктним записам.
- **Неперевірений результат.** Керівник із забезпечення якості виносить рішення «пройдено» або «не пройдено», перш ніж будь-що потрапить до власника.
- **Завислі рішення.** Щонайбільше п'ять відкритих рішень і правило 48 годин: після його спливу рекомендація набуває чинності.
- **Ніщо не вимірюється.** `report` показує частку виконаних завдань, тривалість циклу, частку успішних перевірок якості та навантаження за ролями; `export` записує файли CSV для Power BI.
- **Немає підзвітності.** Кожен запис на дошці фіксується: хто, коли і що змінив.
- **Конфіденційні дані у зовнішніх інструментах.** Обов'язкова політика даних із класифікацією та переліком затверджених інструментів.

## Що ви отримуєте

- **80 спеціалізацій** (стратегія, ресторани, нерухомість, програмне забезпечення, HR, освіта та інші) і понад 330 готових ролей, які додаються одним клацанням.
- **130 готових навичок у 18 групах.** Навичка — це короткий файл, що описує, коли її застосовувати, її кроки, результат і критерій прийняття, тож працівник діє за нею, а не імпровізує.
- **Чотири платформи:** Claude, ChatGPT, Grok і Gemini. Кожен працівник може працювати на своїй платформі.
- **27 мов інтерфейсу** на сайті та в майстрі. Бажана мова — це мова керування всією системою та спілкування з працівниками.
- **Сайт керування** з одного HTML-файлу: дошка, команда, рішення, показники, бібліотека готових команд і механізм уваги, який позначає прострочене та те, що чекає на вашу відповідь.

## Команди

`new`, `build`, `watch`, `rows`, `add-row`, `set-status`, `add-role`, `add-skill`, `skills`, `decide`, `status`, `report`, `export`, `check`, `register`, `selftest`.

## Платформи

| Платформа | Як налаштовується команда |
| --- | --- |
| Claude | Створіть проєкт із назвою вашого проєкту та додайте згенеровану теку. |
| ChatGPT | Створіть проєкт і завантажте файли з теки. |
| Grok | Створіть проєкт, вставте команду Compass в його інструкції та додайте файли. |
| Gemini | Створіть Gem для кожного працівника, вставте його команду в інструкції та додайте файли в розділ Knowledge. |

Завантажуйте файли з теки проєкту в її початковому розташуванні та повторно завантажуйте змінені. Наскільки нам відомо, Grok і Gemini не записують дані в теку напряму, тому переносьте їхні результати до теки самостійно. Описані кроки ґрунтуються на загальнодоступній документації на момент написання; інтерфейси й обмеження визначаються цими платформами та можуть змінитися.

## Поточні обмеження

- Майстер і сайт відображаються 27 мовами, проте створювані файли проєкту (правила, описи ролей, дошка) і сайт керування наразі написані арабською мовою. Працівникам повідомляється, якою мовою працювати, і вони відповідають вам цією мовою.
- Імена файлів, команди та слова статусів дошки залишаються арабською мовою, оскільки інструмент зчитує їх буквально.
- Встановлення у Windows ще не перевірялося на реальному комп'ютері.

## Для розробників

```
git clone https://github.com/HakamiDev/ProjectForge.git
cd ProjectForge
python3 -m forge
python3 -I tests/testforge.py
python3 -I tools/build-single.py
python3 -I tools/build-site.py
```

Вихідний код міститься в `forge/`; `tools/build-single.py` створює однофайловий інструмент у `dist/`. Шаблони містяться в `forge/templates/`, загальнодоступний сайт — у `site/`.
